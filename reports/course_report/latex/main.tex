\begin{abstract}
This project compares DQN and PPO agents on interactive ARC-AGI-3 games. Both agents receive four visual frames and choose from a set of simple actions and click positions. We first evaluate the baseline agents, then add rewards for visiting new screens and memory of previous actions. On the development game ft09, PPO with novelty completes a level in 28 of 60 evaluation episodes, compared with 5 of 60 for its baseline. DQN with 30\% random exploration completes a level in 42 of 60 baseline episodes. Its separate novelty and memory changes perform worse, while the combined version reaches 45 of 60. None of the agents completes a full game. Inspecting a recorded trajectory shows that the original click grid cannot reach any puzzle tile on the second level of ft09. A finer grid reaches those tiles, but first-level performance falls under the same training budget. The best trained condition has a local RHAE score of 0.36\% on ft09; every held-out score is below 0.01\%. The results show some useful exploration, but little reliable progress beyond the first level or transfer to unfamiliar games. Code: \url{https://github.com/TafaraC/RL_Project}.
\end{abstract}

\section{Problem and research questions}
In this project we trained agents to interact with ARC-AGI-3 games without being given their rules or goals. An agent sees the current screen and the available actions, then has to discover which actions make progress. We wanted to find out how much DQN and PPO could learn within a fixed interaction budget, whether exploration rewards and short action histories would help, and what prevented the agents from completing later levels.

DQN is the value-based algorithm covered in the course; PPO is the policy-gradient algorithm not covered in the course. Both share a scaffold built on PyTorch \citep{paszke2019}, NumPy \citep{harris2020} and Gymnasium \citep{towers2024}; the novelty, reset, rollout-memory and inference logic were written and tested for this project. Related methods are DQN's replay and target network \citep{mnih2015}, PPO's clipped objective \citep{schulman2017} and generalized advantage estimation \citep{schulman2016}. Our novelty bonus follows count-based exploration \citep{strehl2008,bellemare2016}, using exact frame counts rather than a learned density model. Learned curiosity signals, such as prediction error in a learned feature space \citep{pathak2017} or random network distillation \citep{burda2019}, extend this idea to large state spaces. We chose exact counts because ARC frames are discrete and can repeat exactly.

\section{Environment formulation and interface}
The agent cannot observe the full game state. We use the last four frames as its history, although this can leave out information from earlier actions. Each 64-by-64 frame contains 16 colour indices. We represent each colour with a binary plane, giving 16 planes per frame and 64 input channels in total. Missing frames are filled with zeros. When a response contains several frames, we append only the newest one. The network receives no internal engine state.

Seven simple actions (RESET, ACTION1--5 and ACTION7) and an $8\times8$ lattice of click centres give 71 actions. ACTION6 carries click coordinates; its legality activates all lattice cells. The finer $16\times16$ representation has 263 actions. Available-action masks come from the public interface. This discretisation is computationally convenient but can remove necessary actions.

The Gymnasium adapter returns the latest frame, action mask and progress information. WIN terminates; 1,000 consumed actions truncate. GAME\_OVER triggers a reset inside the same budgeted episode, clearing visual/action history while retaining the agent's parameters. The initial reset is excluded from this budget, but internal resets count. A selected RESET also clears history. The official framework counts the initial reset, so our notebook permits 1,001 total calls to reproduce this convention. Training decisions and consumed actions are consequently distinct.

Training reward is $+1$ per completed level, $+5$ on WIN, $-0.05$ on death and $-0.002$ per action. The small action penalty encourages progress with fewer actions. Evaluation records levels completed, game wins and actions used, including failed episodes. We also compute local relative human action efficiency (RHAE) scores from the recorded completion counts and human baselines (Table~\ref{tab:rhae}). These are separate from shaped training reward and are not Kaggle leaderboard scores.

\section{Learning algorithms}
\subsection{DQN}
DQN learns an action-value function $Q_\theta(h,a)$ from replayed transitions. The masked Bellman target is $y=r+\gamma(1-d)\max_{a'\in\mathcal A(h')}Q_{\bar\theta}(h',a')$, with a separate target network and Huber loss. True terminals stop bootstrapping; action-budget truncation keeps it. Epsilon-greedy behaviour explores legal actions during training. Network parameters persist across episodes. Replay is used only in training. The target network is copied periodically to stabilise learning.

The CNN has three convolutional layers with 32, 64 and 64 channels, kernels 5, 3 and 3 and stride 2, followed by a 512-unit fully connected layer and the action outputs. Adam \citep{kingma2015} learning rate is $2.5\times10^{-4}$, discount 0.99, batch size 64 and replay capacity 10,000 transitions. Learning starts after 1,000 transitions, updates occur every four decisions and the target is copied every 1,000 gradient updates. Epsilon decays from 1 to 0.05 over 50,000 decisions. Observations are bit-packed to limit replay memory. Run configurations are stored with the evidence.

\subsection{PPO and its update loop}
PPO learns a categorical policy and a scalar value on the same CNN, with one extra value output. During training it samples a legal action and stores the observation, mask, old log probability, reward and value. After 128 transitions, generalized advantage estimation computes
\begin{equation}
\delta_t=r_t+\gamma V(h_{t+1})-V(h_t),\qquad
\hat A_t=\delta_t+\gamma\lambda\hat A_{t+1},
\end{equation}
with terminal, bootstrap and reset-boundary masks applied separately. True terminals use zero next value; truncations bootstrap but stop advantage recursion across episode resets. Advantages are normalised over the rollout.

With $\rho_t=\pi_\theta(a_t|h_t)/\pi_{\mathrm{old}}(a_t|h_t)$, PPO minimises the negative mean of $\min(\rho_t\hat A_t,\mathrm{clip}(\rho_t,0.8,1.2)\hat A_t)$, plus $0.5$ times the value mean-squared error, minus $0.01$ times the policy entropy. Each update runs four epochs over minibatches of 32. Adam learning rate is $3\times10^{-4}$, $\gamma=0.99$, $\lambda=0.95$ and the gradient norm is capped at 0.5. Old masks and probabilities stay fixed during each update. Rollouts store the exact augmented observations, so a history intervention cannot change the likelihood-ratio inputs. The partial final rollout is used for one last update before saving.

Evaluation freezes all weights. PPO samples from its policy; greedy evaluation is a secondary diagnostic. DQN is evaluated with epsilon 0.3, chosen after inspecting development behaviour. Exploration is therefore part of the evaluated DQN policy, and the choice carries selection bias. We do not compare greedy DQN with sampled PPO as if they used the same decision rule.

\section{Experimental protocol}
A recorded shuffle (seed 2026) of the 25 public games selects dc22, ft09, g50t and m0r0 for development and reserves cd82, tr87 and vc33 for final transfer. Each development game is trained separately with independent training seeds 0, 1 and 2 and a target of 50,000 decisions. The runner finishes its last episode, so each run uses about 50,600--51,000 decisions. PPO is evaluated for 20 rollouts per checkpoint, with sampling seeds 100--119 and 1,000 actions. Stochastic DQN evaluations on ft09 also use 20 rollouts. Older stochastic DQN evaluations on dc22, g50t and m0r0 use ten per checkpoint. We retained these shorter runs, so those comparisons have unequal evaluation sample sizes. These seeds control action selection, not game layouts.

We compare three DQN stages, their combined version on ft09 and five PPO conditions. Each training seed produces a separate model. The 60 ft09 rollouts per condition therefore come from three trained models. Table~\ref{tab:results} shows their individual results and the spread across seeds. Development evaluations reuse training games and cannot establish generalisation. The random reference runs seeds 0--2 for 20 episodes per development game. It completes a ft09 level in 2, 5 and 8 episodes and none on the other games. An earlier ft09-only random run with a different random-number schedule gave 5, 9 and 8.

PPO was trained on Windows with Python 3.14.3, PyTorch 2.14.1+cu130 and an RTX 3050 Laptop GPU. DQN improvement runs used Python 3.12.10 on the CPU. Both used arcengine 0.9.3 and arc-agi 0.9.9. The game engine runs on the CPU in both cases. Because hardware differs, elapsed time is not a clean measure of algorithmic efficiency.

\section{Iterative improvements and development evidence}
\subsection{DQN: exploration and no-change memory}
The baseline's greedy policy repeatedly selects a few actions. Training-time completions may therefore come from exploration noise rather than from a capable greedy policy. The first improvement adds a training-only first-visit screen bonus of 0.01, capped at 0.5 per episode, to encourage visual exploration. It does not help: ft09 completion falls from 42/60 to 13/60. The evaluation logs show why. The greedy novelty policy on ft09 (one greedy episode per seed) spends 99.4\% of its actions on moves that leave the screen unchanged, repeats a single action for 99.3\% of all actions and sees about seven distinct screens per episode. An unchanged screen earns no first-visit bonus. The bonus did not prevent these loops, although the logs alone do not explain why the policy continued to choose those actions.

The second improvement targets this failure directly. A per-screen memory records actions that left the latest frame unchanged and masks them when the agent returns to that screen. If every legal action would be masked, the full legal mask is restored. The memory uses public screen history, lasts for one episode and changes action selection without a learned recurrent model.

The memory-only condition disables novelty, isolating the memory from the bonus that preceded it. It changes the behaviour it targets: the greedy memory-trained policy on ft09 repeats its most frequent action for 21\% of actions, with 62\% unchanged-screen actions, against 99\% for both after novelty. Breaking the loop does not by itself produce more completions. The combined novelty-plus-memory checkpoints are evaluated on ft09 under the same 20-rollout, epsilon-0.3 protocol. Seeds 0, 1 and 2 clear a level in 19, 8 and 18 episodes (45/60). This exceeds novelty alone (13/60) and memory alone (25/60), but only slightly exceeds the baseline (42/60), with large seed variation. The combined condition was trained on ft09 only and is not part of the transfer comparison. Applying memory at evaluation time to the baseline DQN gives 47/60; this diagnostic does not show a benefit of training with memory. Earlier DQN evaluations did not save their configurations, so their epsilon and memory settings are taken from directory names and scripts.

\subsection{PPO: novelty, then explicit action history}
Baseline sampled PPO rarely completes the first ft09 level. We add a diminishing bonus $0.01/\sqrt{N(s)}$ for the exact newest screen, capped at 0.5 per episode. Counts persist across internal death resets and reset at the next episode. Unlike DQN's first-visit bonus, repeated screens keep a decreasing reward. Pooled ft09 level completion rises from 5/60 to 28/60, but seed 2 dominates the result with 20/20, against 4/20 for each other seed.

Watching the agent repeat ineffective actions led us to add action history to PPO. We wanted the policy to distinguish a new attempt from a repeated action that had already failed. Sixteen binary planes record the previous simple action (seven planes), the previous click cell (one), and counts of repeated actions and unchanged screens (four planes each). Each counter activates one additional plane per step, up to four. We prepend these planes to the visual history, giving 80 channels. Memory clears on resets and continues across level transitions. The reward and PPO objective stay the same. Because this version also uses a finer click grid, we tested novelty with the same finer grid but no memory. We also tested memory without novelty. Memory plus novelty completes a level in only 3/60 episodes, compared with 10/60 for the finer-grid novelty control. Memory alone reaches 6/60. Under this budget, adding the history did not help.

The larger input and action space may need more training, but we did not test a longer budget.

\subsection{Comparison, variability and cost}
On ft09, DQN with evaluation exploration exceeds both the sampled PPO baseline and pooled novelty PPO (Table~\ref{tab:results}). This is a narrow development comparison, not evidence of general superiority: the evaluation policies differ and epsilon was chosen on development data. No DQN condition completes a level on the other three development games. PPO completes none on dc22 and m0r0; memory-only PPO completes one g50t level in 60 rollouts, and all other g50t conditions complete none. Single successes do not show reliable adaptation.

All PPO greedy evaluations complete zero levels. Earlier greedy evaluations of improved DQN on ft09 contain one episode per seed, against 20 for stochastic evaluations, so greedy and stochastic rates cannot be compared with equal precision. Every development episode uses its full 1,000-action budget because no game is won. Figure~\ref{fig:learning} shows training-time progress, which is stronger than the frozen-policy results.

Table~\ref{tab:rhae} applies the published RHAE formula to our saved episodes. RHAE rewards efficiency as well as completion. A level solved in $a$ actions scores $\min(1.15,(h/a)^2)$, where $h$ is the human baseline, and a game score weights level $l$ by $l$ over all of the game's levels. Because ft09 has six levels, clearing only level one is worth at most 5.5\% of the game. Successful episodes clear it in a median of 372 actions (DQN baseline) and 232 actions (novelty PPO), against a human baseline of 43, so even they score little. RHAE ranks the conditions in nearly the same order as completion counts. The best pooled ft09 score is 0.36\% (DQN baseline and combined DQN), or 0.54\% with evaluation-time memory. RHAE also widens the gap between the best agents and random play: random clears ft09 level one in 15/60 episodes but needs a median of 529 actions, scoring 0.013\%. Every condition scores below 0.01\% on the held-out games. These are local scores on public games, not Kaggle leaderboard scores. Our counts exclude the initial reset. Including it would add one action to the first-level completion count and slightly reduce the nonzero scores. These values reconstruct scores from logs; they are not scores returned by the official gateway.

Across 12 training runs per stage, DQN baseline, novelty and memory take 7.34, 7.17 and 7.04 hours, with about 609,000 decisions each. Combined DQN adds 1.81 hours for three ft09 runs (152,726 decisions). PPO baseline and novelty take 1.26 and 1.38 hours; grid control, memory plus novelty and memory only take 1.53, 1.80 and 1.80 hours. These figures exclude evaluation, smoke tests and failed attempts. Evaluation cost is reported separately. All frozen evaluation, development and held-out together, took 0.85 hours for DQN (798 episodes) and 3.58 hours for PPO (2,295 episodes, including greedy diagnostics): about 3.8 and 5.6 seconds per episode. The held-out evaluation alone took 20 minutes. In the evaluation CSVs, wall time is cumulative, so a file's cost is its final value. CPU DQN against GPU PPO remains a hardware confound.

\section{Behavioural diagnosis and final transfer}
In one sampled novelty-PPO trajectory, the agent clears ft09 level one and then makes 690 decisions without further progress. We inspected the development game to understand why. The original click grid reaches all eight first-level tiles but none of the 13 second-level tiles. The agent therefore cannot solve that level with its available click positions, however well it learns to choose between them. A 16-by-16 grid reaches all 13 tiles. This fixes reachability, but the finer-grid control performs worse on level one than novelty PPO with the original grid. Having more actions may make exploration harder, although we did not measure that effect separately.

The greedy agent repeatedly toggles a tile's colour without solving the puzzle. Since the pixels change, a no-change mask would not stop this cycle. Counting new screens can also reward visual changes that do not help solve the game. A useful next step would be to test click positions based on visible objects, together with memory that records the outcomes of earlier actions. These changes would need to be compared under the same interaction budget.

\section{Submission, limitations and conclusion}
The submission includes notebooks for four DQN conditions and five PPO conditions. Each contains the inference code and loads NumPy weights from the accompanying model dataset, which must be attached in Kaggle. The notebooks use the official Agent interface, install the competition-provided offline wheels and require CUDA. We checked that the exported networks produce exactly the same logits as the original PyTorch networks. Training used a Windows/Python 3.14 CUDA build; Kaggle must use its own Linux environment and installed PyTorch instead. We tested all nine agents locally through the official agent loop on the four development games, and checked the nominated notebook's parquet output. The offline installation and live Kaggle gateway have not been tested. An ordinary notebook run writes the starter's placeholder parquet; only a competition rerun produces an official score.

We selected DQN baseline seed 1 with epsilon 0.3 as the competition entry, using development results before running the held-out evaluation. PPO novelty seed 2 is the PPO alternative. Both still use the 8-by-8 grid and have its reachability limitation. The selected DQN checkpoint completed an ft09 level in 20/20 episodes, but that is the best seed's result rather than the three-seed average. Each notebook uses the same model for every game. Weights stay fixed during evaluation; visual and action memories reset between games, with no information carried from one game to the next.

We inspected development-game source and state when investigating click coverage and trajectories. Training and inference use only public observations, legal actions and previous chosen actions. We did not inspect held-out source or solutions, or use scripted game-specific action sequences. One PPO attempt failed because of a host-memory allocation error and was restarted; its partial outputs are excluded. Other limitations include missing configurations for some older runs, different hardware for DQN and PPO, selection of checkpoints using development results, and only five held-out rollouts per checkpoint and game. No official submission score or published Paper Track link is available.

PPO's novelty reward increased first-level completion on ft09 from 5/60 to 28/60, but adding action history reduced it. For DQN, combining novelty and no-change memory reached 45/60 compared with the baseline's 42/60, while either change alone performed worse. Results varied considerably between training seeds. Neither algorithm completed a full game, and almost every held-out episode ended without completing a level. The trajectory inspection helped explain part of the difficulty: some necessary clicks were unavailable, and repeated visual changes could occur without useful progress. Improving the action representation and testing how the agents use earlier outcomes are the next practical steps.
